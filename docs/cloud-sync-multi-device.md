# 多设备题库同步机制

## 目标

- 同一教师账号可以在多台电脑离线录题，联网后自动汇总。
- 不同 UUID 但同名的学科、同一学科下的同名章节、同名标签，以及摘要相同的图片，归一为一个云端身份。
- 不同 ID 的题目全部保留；内容相似只进入题库查重，不作为同步冲突自动删除。
- 同一实体基于同一云端版本被两台设备分别修改时，保留双方内容并要求人工确认。

## 身份模型

SQLite 业务表继续使用本机 UUID。`cloud_entity_mappings` 保存当前教师账号下的本地 ID 与云端规范 ID，因此同步不需要批量改写题目、草稿、试卷等业务外键。

服务端通过 `sync_natural_keys` 为下列实体确定规范身份：

| 实体 | 自然键 |
| --- | --- |
| 学科 | 规范化名称 `nameKey` |
| 章节 | 云端规范学科 ID + `nameKey` |
| 标签 | 规范化名称 `nameKey` |
| 图片资源 | SHA-256 |

两个离线客户端同时创建相同自然键时，服务端原子地保留一个规范 ID，并通过 `sync_entity_aliases` 记录另一个临时 ID。客户端收到 `merged` 结果后保存映射，再上传依赖它的章节和题目。

## 同步顺序

一次同步先拉取云端变化，建立或更新身份映射，然后应用本地变更。上传按依赖层分阶段执行：

1. 题型
2. 学科
3. 章节
4. 标签
5. 图片资源
6. 题目

删除操作按相反顺序执行。每完成一层都会重新捕获本地实体，因此前一层返回的规范 ID 会用于后一层的外键。

服务端增量游标仍按变更时间分页，不能假定父实体一定与子实体出现在同一页。客户端遇到科目、章节、标签或图片尚未到达造成的外键失败时，会把云端载荷保存为后台待补全项；后续分页处理完毕以及下次同步开始时，都按上述依赖顺序自动重试。只有本机与云端确实都发生内容修改时才进入人工冲突列表。

## 首次同步

首次绑定前，客户端读取本地有效实体数量以及云端有效实体数量。内置题型和云端删除标记不计入“非空”。

- 两边都空：直接建立同步关系。
- 只有本机有数据：以本机建立云端副本。
- 只有云端有数据：下载云端数据。
- 两边都有数据：默认智能合并；不同题目保留，同名分类及相同图片自动归一。

整库覆盖属于恢复/维护操作，不由后台自动同步触发。

## 发布顺序

服务端接口增加了有效实体统计和 `merged` 推送结果。发布时必须先部署 `zhitiku-cloud` 0.2.1，并依次执行迁移 `0004_multi_device_identity.sql`、`0005_legacy_alias_canonicalization.sql`，确认健康检查通过后，再分发桌面端 0.1.73。旧桌面端的普通同步仍兼容新服务端；新桌面端首次同步预检依赖新服务端字段。桌面端 0.1.73 还修复了旧实体别名删除在云端合并后被误报为“合并结果缺少本地实体”的兼容问题。
