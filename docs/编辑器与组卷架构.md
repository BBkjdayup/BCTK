# 编辑器与组卷架构

## 数据流

1. 日常录题使用 Tiptap。新题的题干、选项、答案和解析保存 `schemaVersion: 2`、Tiptap JSON、HTML 缓存和纯文本缓存。
2. SQLite 仍把每个富文本字段作为 JSON 保存；纯文本单独进入搜索字段。旧 `schemaVersion: 1` HTML 数据不做批量改写，打开后仍可读取。
3. 组卷时，题目会复制为试卷快照。canvas-editor 从快照生成第一版分页稿，用户可以在画布里继续排版。
4. canvas-editor 的原生 `data`、`options`、编辑器版本和来源签名保存到 `papers.layout_json`。题目或标题变化时只提示排版已过期，不自动覆盖手工内容。
5. “直接打印”调用 canvas-editor 自带的打印命令。软件不提供 PDF 生成，也不调用 LibreOffice。
6. DOCX 导入/导出继续走 Rust OOXML 模块。它使用题目快照中的兼容缓存和原始 OOXML，不依赖 canvas-editor 排版 JSON。

## 兼容与迁移

- 数据库第 9 个迁移只给 `papers` 增加可空的 `layout_json` 和 `layout_updated_at_ms`，旧试卷无需转换。
- Tiptap V2 仍保留 `html` 和 `plainText`，所以现有题库搜索、预览、重复检测和 DOCX 路径不需要同时重写。
- 保存前 Rust 会检查编辑器类型、版本、JSON 根节点和大小限制；HTML 的危险标签与内联事件检查继续生效。
- 试卷复制时同时复制排版 JSON；用户可保留原排版继续修改，也可按当前题目重新生成。

## 当前边界

- 编辑器选择、普通粘贴和从 WPS 带入的 PNG/JPEG 会先由后端校验，再按 SHA-256 写入受管资源目录；Tiptap JSON 和兼容 HTML 只保存资源 ID，相同图片不会重复落盘。
- canvas-editor 初次生成会保留 Tiptap 的常用文字样式与公式；试卷 DOCX 支持受管图片、原生表格和可编辑公式。嵌套表格、外链图片和无法结构化的原始 OOXML 仍由 Rust 安全检查拒绝并给出位置。
- “直接打印”使用 Windows/WebView2 的系统打印流程，实际可用打印机和驱动由操作系统管理。

## 发布检查

- 固定 Tiptap 与 canvas-editor 的精确版本并提交 `pnpm-lock.yaml`。
- 运行 `pnpm lint`、`pnpm test`、`pnpm build` 和 `cargo test --locked`。
- 每次发布重新执行生产依赖许可证清单检查，并将 `THIRD_PARTY_NOTICES.md` 随安装包分发。
- 本方案不使用 Tiptap 的付费 Pro/Cloud 功能，也不使用 LibreOffice；引入新依赖前仍需单独复核其许可证。
