# 软件自动更新说明

## 客户端行为

- Windows 桌面端启动约 8 秒后自动检查 `https://api.tktiku.cn/updates/latest.json`。发现新版本后，软件在后台下载并完成发布签名校验，不打断录题、组卷或导出。
- 用户正常关闭软件时，题目编辑、Word 导入和试卷编辑的未保存内容保护会先执行；全部允许关闭后，已验证的更新会以 Windows `passive` 安装方式自动安装并重启软件。安装器显示简短进度，但不要求用户点击“下一步”。
- 如果软件下载或安装器启动失败，软件继续正常使用或正常关闭；下一次启动会重新检查和下载。关闭前下载尚未完成时，也会在下一次启动重新下载。
- 用户仍可在“系统设置 → 关于软件 → 软件更新”手动检查，并选择立即下载和安装。
- 安装包必须通过 Tauri Updater 的发布签名校验；HTTPS 服务器返回的下载地址或文件即使被篡改，没有私钥签名也不能安装。
- 更新检查或下载失败不会阻止软件启动，也不会影响本地录题、组卷或题库数据。

`0.1.74` 是第一版带自动更新能力的客户端。已经安装 `0.1.73` 或更早版本的用户需要手工安装一次带更新器的版本。已经使用更新器的老用户也需要手工安装一次采用“后台下载、退出安装”方式的版本，后续版本才会按新流程更新。

## 签名边界

- 客户端只内置更新签名公钥，公钥可以公开。
- 官方更新私钥和口令保存在源码仓库之外，不提交 Git、不放入服务器公开目录，也不包含在普通源码或安装包中。
- 更新签名与 Windows Authenticode 代码签名是两套机制。Updater 签名用于验证软件更新；没有 Authenticode 证书时，Windows 仍可能显示“未知发布者”。
- 私钥丢失后，已安装客户端无法验证由新密钥签发的更新，因此维护者需要单独进行加密离线备份。

## 社区构建

普通源码构建不需要官方更新私钥：

```powershell
pnpm install --frozen-lockfile
pnpm build:installer
```

该命令使用 `src-tauri/tauri.local-build.conf.json` 关闭更新签名产物，仅生成普通 Windows 安装包。

独立分发修改版前，应设置自己的应用标识、更新地址、公钥和签名私钥。不要复用官方品牌或把第三方构建描述为官方更新。

## 官方维护构建

仓库中的 `pnpm release:update` 是维护者使用的签名发布入口。它要求仓库外的官方私钥与受保护口令；缺少这些材料时应当停止，而不是生成未签名的伪官方更新。

正式发布顺序应为：

1. 完成测试和生产构建。
2. 生成签名安装包、签名文件和版本化更新清单。
3. 先上传安装包并核对公开下载摘要。
4. 最后原子替换更新清单，避免客户端读到尚不存在的文件。

## 回滚原则

- Tauri 默认只接受高于当前版本的更新，不通过降低清单版本自动降级。
- 出现问题时应先停止继续分发，再修复并发布更高的新版本。
- 安装包升级不应删除或覆盖用户的本地 SQLite 题库。

## 官网与桌面版本一致性

官网构建从 `package.json` 注入后备下载版本。发布官网前，应确认公开更新清单、下载地址和官网版本一致，避免页面介绍与实际安装包不匹配。
