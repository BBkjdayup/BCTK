# TK试题题库软件技术方案说明

这份说明面向非技术人员，记录本项目为什么采用“方案 A + W1”，以及每个技术点会带来什么影响。

## 1. 桌面软件外壳

### 方案 A：Tauri（已选择）

Tauri 用 Windows 自带的 WebView2 显示 Vue 界面，用 Rust 处理数据库和文件。优点是安装包与内存占用通常较小，文件权限可以集中控制；代价是首次在开发电脑上编译时必须安装微软 C++ Build Tools。

### 方案 B：Electron

Electron 会把一个完整浏览器一起放入安装包。开发生态成熟、排查界面问题方便，但安装包更大、占用内存更多。对本项目这种长期离线、以表格和文档为主的软件，收益不足以抵消体积成本。

### 方案 C：纯 Windows 原生界面

例如 C# + WinUI/WPF。它与 Windows 结合最深，但界面预览转代码的工作量更大，也会形成另一套前端技术。若将来需要大量 Office 深度自动化，可以重新评估；第一版不采用。

## 2. Word 处理

### W1：直接处理 DOCX/OOXML（已选择）

`.docx` 本质上是一个包含 XML、图片和关系文件的压缩包。软件直接读取这些文件，因此用户电脑不必安装 Word，也能导入和导出。

本项目的 W1 是“受限但可控”的实现：

- 只接受普通 `.docx`，拒绝宏、ActiveX、OLE、外部链接、异常压缩包和危险路径。
- 底层解析器能读取普通段落文字，提取 Word 原生公式和受支持的 MathType 内容并转换为可编辑公式节点；无法安全结构化的原始片段会形成明确诊断，不会静默丢失。
- 能安全提取主文档中的 PNG/JPEG 图片，拒绝外部图片、危险关系、异常尺寸和过大资源，并写入软件管理的资源目录。
- 模板通过内容控件标签或 `{{ZT_名称}}` 标记可替换区域。
- 已保存试卷可以通过组卷页或历史试卷进入导出流程。软件在一个数据库快照中读取试卷、题目快照和模板记录，核对行版本与模板摘要，只替换 `ZT_QUESTIONS` 等受支持区域，并在重新打开成品复检成功后才报告导出完成。
- 试卷和题库 Word 导出支持受管 PNG/JPEG 图片、原生 Word 表格和由 LaTeX 节点生成的可编辑 OMML 公式。嵌套表格、外链图片、缺少结构化数据的公式或原始 OOXML 仍会明确指出具体题目并拒绝导出，避免格式内容被静默丢弃。题库 Excel 导出使用纯文字列，不嵌入富内容。
- 软件内预览重点表达内容和结构，不承诺与 Word 的分页完全一致。

### W2：调用本机 Microsoft Word

优点是分页和 Word 最接近；缺点是每台电脑都必须安装兼容版本的 Word，自动化容易受到弹窗、权限和 Office 更新影响，不符合“独立离线软件”的目标。

### W3：购买商业文档组件

功能最完整、兼容性通常更好，但需要持续支付授权费用，并核对离线分发许可。第一版先用 W1，只有实际样本文档证明 W1 无法覆盖时再评估。

## 3. 本地数据库

SQLite 把数据保存在一个本机数据库文件中，不需要安装服务器。它支持事务：一次保存要么全部成功，要么全部撤销，避免出现“题干保存了但答案没保存”的半成品。

数据库还使用：

- **外键**：保证题目引用的学科和章节真实存在。
- **约束**：限制题型只能是需求规定的六种，禁止空名称和损坏的 JSON。
- **全文检索索引**：搜索题干、答案、解析和标签时无需逐条慢慢扫描。
- **迁移脚本**：软件升级时按版本逐步升级数据库，而不是直接覆盖旧题库。
- **完整性检查**：启动、备份和恢复等关键节点核对数据库结构。

## 4. 数据保存位置

默认数据根目录是用户“文档”中的 `教师题库`。如果系统无法提供文档目录，才退回软件专用数据目录。

用户更换数据位置时，软件不会跨磁盘直接“剪切”目录，而是冻结写入后创建 SQLite 一致性快照，复制数据库、资源、模板、备份和导出目录，并逐文件及整目录校验。全部通过后，软件把新的数据根记录在位于数据目录之外的 LocalAppData 引导记录中，重启后再做一次复检才启用；失败时继续使用原目录，旧目录始终由用户决定何时删除。

更换数据位置必须执行四步：复制到新目录、校验新副本、切换软件配置、保留旧副本。旧数据不会在切换完成后立即删除，避免移动中断造成唯一副本丢失。

### `.tqb` 完整备份

`.tqb` 是本软件的完整备份容器，里面包含 SQLite 数据库一致性快照、题目资源和受管 Word 模板。创建时不是直接复制正在使用的数据库文件，而是先让 SQLite 生成一个一致快照，再重新执行数据库标识、完整性、外键、版本和题库身份检查。

归档内有一份版本化清单，记录每个文件的相对路径、类型、字节数和 SHA-256。软件写完后会重新打开整个归档并逐项核对，只有全部通过才显示“备份成功”。读取外部 `.tqb` 时会在 ZIP 库分配大量内存前先限制中央目录、条目数和普通 ZIP 大小，并拒绝 ZIP64、重复或大小写冲突路径、符号链接、路径穿越、加密成员、隐藏重叠数据和异常压缩比例。

当前版本已经连通“创建完整备份 → 受控暂存解压 → 候选数据库与文件摘要复检 → 恢复前自动备份 → 重启切换 → 失败或异常中断回滚 → 保留旧数据”的完整恢复流程。若当前数据库已经损坏、无法生成标准 `.tqb`，软件会进入救援模式：先把现有数据库、模板和资源目录原样隔离保留，再切换到通过校验的备份，不会把损坏数据悄悄删除。

## 5. 题目富文本

题干、选项、答案和解析采用“富文本 JSON + 可搜索纯文本 + 受管资源引用”的保存方式：

- 富文本 JSON 保存经过安全过滤的 HTML、纯文本和可选来源信息，是当前显示内容的主体。
- 纯文本是可重建的搜索缓存，用于快速检索和重复检测。
- 从 Word 导入、编辑器选择、普通粘贴或从 WPS 带入的 PNG/JPEG 图片按 SHA-256 内容摘要写入受管资源目录，相同图片只保存一份；题目中的节点引用负责说明图片出现在哪个题干、选项、答案或解析位置。
- 图片引用会跟随 Word 导入草稿、普通编辑草稿、正式题目和试卷快照保存，避免某个页面关闭后图片关系丢失。
- 当前新内容的图片引用已经完整记录；旧版本遗留图片和部分原始 OOXML 仍不主动批量迁移，因此无引用资源永久清理保持关闭，防止索引不完整时误删文件。

## 6. 重复题检测

第一阶段使用标准化文字的 SHA-256 指纹判断完全重复：去除无意义格式差异后，对题干、选项和答案计算固定长度摘要；这与需求文档规定的判断字段一致。指纹相同会提示用户选择跳过、覆盖或保留两份；数据库不会擅自删除。

疑似重复使用有上限的 Unicode 双字符组相似度：每个内容字段先做 NFKC 标准化，并只比较最可能的有限候选，避免题库很大时无边界扫描。当前阈值为 82%；结果只用于提醒，绝不代替教师做最终决定。

## 7. 草稿与回收站

- 编辑页面每 60 秒保存一次草稿，手动保存成功后再清理对应草稿。
- Word 导入审查也使用 SQLite 固定草稿槽位：保存来源文件名和大小、逐题校对内容、重复候选与处理选择，不保存原始绝对路径；恢复后会重新检查重复候选是否仍然有效。
- 两类草稿都会在切换页面和关闭软件时提示并尝试落盘；待处理草稿数量来自数据库，不依赖浏览器缓存。
- 回收站提醒期限可由教师设置（默认 30 天）；达到期限后仍只提醒或等待手动清理，不自动静默删除。
- 永久删除是不可逆操作，必须再次确认，并只删除已经进入回收站的数据。

## 8. 组卷与批量编辑

随机抽题使用独立后端命令。前端提交学科、多个章节、任一/全部标签、已选题目 ID 和计划数量；SQLite 直接返回各题型候选数量，并在抽取时只批量水合最终命中的题目，不再分页传输全部候选的题干、选项、答案、解析和资源引用。普通题库分页也会批量读取选项、标签和资源引用，避免逐题查询。手动选题使用真实分页，替换题目时只列出同题型、当前筛选范围内且尚未加入试卷的候选，并保留原题在试卷中的位置。

当前新建试卷统一使用手动组卷模式；旧版 `generation_config_json` 字段和自动组卷标识继续保留为只读兼容数据，使升级前创建的试卷仍可打开、复制和按原题型范围替换题目。历史试卷列表采用受限分页完整读取：默认每页 100 份、最多 500 页/5 万份，并在读取期间检查总数漂移、重复标识和提前空页，避免超过 500 份后静默漏数据。

批量编辑采用一个 SQLite 事务：先核对所有选中题目的版本、回收站状态、目标学科/章节和标签，再统一提交。只要其中一道题在别的窗口被修改，或某个分类已经不存在，整批操作都会撤销，不会出现“一半更新、一半失败”。

## 9. Windows 安装包

Windows 版采用 NSIS 安装包，并使用 WebView2 `downloadBootstrapper` 模式：电脑已有 WebView2 时不下载；缺少运行环境时安装阶段需要联网补齐。安装完成后，题库管理、录题、组卷、导入、导出和备份等本地功能可以离线使用。

当前安装器使用简体中文和“仅为当前用户安装”模式，普通使用不需要把软件安装给电脑上的所有账户。正式 x64 Release 已完成构建；每个发布版本的实际测试数量与结果以对应 GitHub Release 中实际记录的验证结果为准，不在通用技术方案中长期写死。安装包未购买商业代码签名证书，因此 Windows 可能显示“未知发布者”或 SmartScreen 提示；这不等于文件损坏，但对外公开分发前仍应购买代码签名证书并加时间戳。

如果以后更重视下载体积，可改成联网引导安装 WebView2；代价是首次安装必须联网。

软件启用单实例保护：重复双击时只唤醒已经打开的主窗口，不同时启动两个界面去修改同一个数据库。生产界面还启用了内容安全策略，只允许加载本地脚本、样式和经过允许的图片资源。

首次启动会在真实用户“文档”目录创建 `教师题库` 数据目录。因此自动构建阶段只核对二进制文件、版本、摘要和签名状态，不在开发者真实账户中直接启动；安装、覆盖升级和卸载的数据保留测试应放在 Windows Sandbox、虚拟机或一次性测试账户中执行。

## 10. 当前边界

第一版不包含账号、云同步、网页端和多版本试卷。这些功能会引入服务器、身份认证、同步冲突和隐私合规等全新问题，不能只在现有界面上增加几个按钮，因此按需求留到后续版本。
